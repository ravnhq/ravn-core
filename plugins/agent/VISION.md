# Vision

This repo exists so that every Ravn engineer, in whatever harness they use, walks the same high-quality golden path for engineering work.
It serves Ravn engineers and the agents they run, and it turns proven engineering workflows into skills backed by scripts.
It owns exactly one thing: the set of Ravn agent plugins - their skills, scripts, MCP configuration, and manifests. Today that set is `ravn-core`; the apps and mods plugins that share this repo follow their own tier's `AGENTS.md` instead.

## Every supported harness is first class

Harness agnosticism is non-negotiable.
Plugins are described by the open agent-plugins.org schemas, not by any one harness's private format.
A feature that works fully in one harness and degrades in the others is refused, even when the gain there is large.
A harness joins the supported list only when every existing skill passes its evals there, or its live check if it is subjective.

## Thin skills, real scripts

A skill is a thin SKILL.md that tells the agent when and how to act, and scripts do the deterministic work.
Moving logic from prose into a bundled script is welcome.
All bundled scripts are TypeScript on Node, so there is one install and one test setup on macOS, Windows, and Linux.
Scripts may use the engineer's existing CLI logins, such as gh, and never ship or store credentials.

## Proven skills, strict evals from v1

Every skill merges with proof that it works; a skill without that proof does not merge, however useful it looks.
Until v1, the proof is a live check: run the skill in Claude Code, Codex, Cursor, and Pi and confirm its observable behavior.
From v1, a structural skill, one whose outcome a check can confirm, is proven by strict evals, and they are non-negotiable; v1's first full eval run sets the baseline every structural skill must pass.
A subjective skill, one whose outcome only judgment can grade, skips evals and keeps the live check.
Skills are authored deliberately by people; skills generated by agents from session history are not merged.
A third-party skill may be adopted and adapted when it meets the same proof and harness bar as our own.

## One golden path

The plugins encode generic, reusable engineering workflows that work across Ravn clients and projects.
A workflow belongs here only as the Ravn way, not as one engineer's personal preference.
The set may be split into several plugins so people install what they need, and every plugin holds the same bar.

## Scope

It is not a harness, not an agent runtime, and not a home for client-specific or project-specific skills.
It does not ship MCP servers that need personal credentials to internal or third-party services, for now.
It is open source under the MIT license, and Ravn decides what merges.

A change aligns when it adds or sharpens a generic engineering workflow as a thin skill backed by scripts, proves it works, and works equally in every supported harness.
A change should be resisted when it favors one harness, lands without proof that it works, encodes one client's or one person's way of working, is agent-generated, or needs personal credentials.
