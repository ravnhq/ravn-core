# Fresh install

Run from the test-owning package with the runner chosen in [the entry](../SKILL.md). The target repo owns the vendored directories and settings. The Vitest block was verified with Oxlint 1.93.0, Vitest 3.2.7 and 5.1.0, and @effect/vitest 4.1.3. A version change requires the self-check; Oxlint JS plugins are alpha.

1. **Survey.** Record test locations and filenames, direct `effect` or `@effect/vitest` dependencies, the runner config, hooks and full test command, and lint and test commands in CI. Run lint, typecheck and tests before edits. Record absent commands as such and keep these results for comparison.
2. **Vendor.** Run `node <skill-directory>/scripts/install.ts`. The default is `tools/oxlint/bad-test-terminator/`; pass another relative location only if the repo keeps lint tooling elsewhere. The copy includes two plugin entry points, `rules/`, `shared/`, and `UPSTREAM.md` with file hashes. Leave the Effect plugin unregistered without Effect. Exclude the vendored directory from lint and from typecheck if its `.ts` imports cause TS5097.
3. **Pin matching packages.** Read the lockfile's Oxlint version, or query `npm view oxlint version` when absent. Pin both `oxlint` and `@oxlint/plugins` to the exact same version in dev dependencies, without changing other ranges. Without an existing config create `.oxlintrc.json` with `{"categories":{"correctness":"off"}}` and a `lint` script running `oxlint --deny-warnings`.
4. **Merge the block.** Run `node <skill-directory>/scripts/config.ts <runner>` with `vitest`, `jest`, `bun`, or `node`; add `--effect` for direct Effect dependencies in Vitest. Merge `ignorePatterns` and `jsPlugins`, then append the guard override so it wins over earlier matching overrides. Keep all five bundled patterns for one runner plus any extra test paths. For mixed runners partition the patterns so each test gets one matching guard block. Include helpers in test directories. Update `specifier` and ignore paths for a custom destination; retain existing guards for the same constructs. Confirm the config diff preserves existing lines apart from insertion punctuation.
5. **Prove the guards bite.** Run `node <skill-directory>/scripts/verify.ts <test-directory> --runner=<runner>` in a test directory matched by the override. Require the selected banned and allowed fixtures to match the block and the verifier to exit 0. The fixtures and verifier stay as bundled. A `FAIL` names a missing or spurious rule; fix the configuration and rerun. A new config, file pattern, or Oxlint version invalidates this result.
6. **Guard the runtime.** Follow [Runner setup](runners.md) for config and hooks, then run its checker against the same CLI options CI uses. Require exit 0 and report which protections apply on this version and which do not.
7. **Repeat in fresh processes.** Add `test:repeat` using [the runner command](runners.md) and the installed `tools/oxlint/bad-test-terminator/repeat.ts`. Run it through the package manager. It stops on the first failing run.
8. **Settle findings.** Run lint, typecheck, tests, and `test:repeat`. List each finding by rule and file:line; record seed and test name for order/repeat failures. When cleanup was requested, [fix the finding](../SKILL.md#fixing-a-finding) or [prune or rewrite](../SKILL.md#prune-the-suite). Otherwise add a final baseline override after the guards: match only the files with findings and disable only the exact rules they trigger. Use `plugins: ["vitest"]` or `["jest"]` for those runners, or `[]` for Bun/Node. Each fix or deletion removes its baseline entry. Keep repeat failures visible; report the first seeded case and remove an unresolved flaky test with its seed and reason only after three fix rounds. Finish with lint and the self-check green.
9. **Wire CI.** Put lint before the tests when it was added, and the repeat run after them. If repeat takes more than a minute locally, use a scheduled workflow with the same setup. Report when no workflow exists to extend.
10. **Record and report.** Fill `UPSTREAM.md` with the merged block, file patterns, runner settings and hooks, repeat command and CI location, baseline entries, and deviations from bundled files. Baselines belong only in the Baseline field. Update test guidance for the checks that changed. Inspect `git status --short` as well as `git diff`; prove what is actually installed and report before/after results, findings and their disposition.
