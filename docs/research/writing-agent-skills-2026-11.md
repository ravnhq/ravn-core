# Writing agent skills that work

Research window: August 18–November 18, 2026. This is a reading of recent arXiv preprints and first-hand practitioner guidance, not a benchmark run on `ravn-core`.

**The authoring rule:** route on what distinguishes the request, state what must be true at the end, and put only the non-obvious procedure on the path to that result. Test skill selection, required behavior, and the final artifact separately. A skill can pass any one of those checks and fail the other two.

## What the evidence supports

| Authoring decision | Evidence and limits |
| --- | --- |
| **Write the description against its nearest sibling.** Name the concrete decision or artifact the user wants. Cut topic words that both skills could claim. Test positive requests, plausible wrong routes, and requests that should load nothing. | OpenAI's September 11 [Astra field guide](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) reports that Codex shortens descriptions when the catalog budget fills and that broad or contradictory descriptions load irrelevant skills. [SkillContrast, October 8](https://arxiv.org/html/2610.11650v1) isolates a related effect: on 1,235 requests, keeping text that distinguished similar candidate skills produced 54–72 more clean top-three hits than query-similarity text selection at matched lengths. The study tests a reranker, not wording changes to `description` or native harness invocation. |
| **Disclose a branch at its decision point.** Put the entry decision and common gates in `SKILL.md`. Link to the relevant file from the step that needs it. Keep mandatory constraints in view when following them is essential. | Workday's [progressive-disclosure report, September 28](https://arxiv.org/html/2609.35692v1#Sx4.T1) compared loading all skill bodies with starting from metadata and loading only the selected body. At 50 skills, the three Qwen setups used 71–82% fewer tokens; in one setup, latency rose 15% because loading added a model call. The experiment used synthetic tasks and a 32k context. It does not predict this repo's savings from moving Markdown into `references/`. [Agent Skill Evolution, October 4](https://arxiv.org/html/2610.04832v1#S5.SS2) found that on-demand loading retained about half the added-rule action gain on average in its sandbox. A reference that never gets read saves tokens by losing the behavior. |
| **Write a contract first; prescribe a step when skipping it changes the result.** Name prerequisites, a concrete command or resource when needed, the expected output, the acceptance check, and what invalidates earlier proof. Leave interchangeable methods open. | [Downstream Utility, October 6, Table 6](https://arxiv.org/html/2610.08875v1#S4.T6) derives 17 practices from execution, recovery, and artifact differences. Across 87 SkillsBench tasks and nine model–harness configurations, the same skills helped some setups and hurt others on about 37% of tasks. These are derived practices, not 17 isolated experiments, and the skill conditions explicitly asked the agent to use the skill. [Agent Skill Evolution](https://arxiv.org/html/2610.04832v1#S5) found the strongest gains for checkable rules that introduced commands or paths absent from the old skill; its study underrepresents permission guardrails and conditionals. |
| **Pass artifacts between phases, not just a list of steps.** State what each phase consumes and produces, and when a changed upstream result forces a rerun. Script deterministic gates; keep judgment in prose. Delegate only with a bounded input, output, and write scope. | [Downstream Utility, §4.3](https://arxiv.org/html/2610.08875v1#S4.SS3) found that stage objectives or artifact dependencies beat invocation order alone; the added benefit of a dependency graph over stage objectives concentrated in small groups of five- and six-skill tasks. [HEXIS, September 24](https://arxiv.org/html/2609.30123v1#S5.SS3) reports a mean 16.1 percentage-point gain from executable transitions versus Skill + ReAct across its benchmark and executor matrix. That is evidence for explicit gates, not a reason to add a runtime to `ravn-core`. [Subagents vs Agent Skills, September 7](https://arxiv.org/html/2609.09233v1#S4) found subagents helped with contract-shaped packages on a 64-task subset and consumed more total tokens. With the original curated packages, inline use matched or beat delegation. The package sets also differed in content. |
| **Exercise the documented command on an installed copy.** Keep environment and version facts in their source of truth. After changes to a runtime, script, artifact format, or tool, rerun the checks whose assumptions changed. | [When Agent Skills Go Stale, November 17](https://arxiv.org/html/2611.22525v1#S4) used successful executions to build targeted environment checks and replayed them without a model call. Selective checks caught some stale assumptions but missed changes outside what they observed. The study used controlled one-change transitions and two models from one family. The practical lesson is to rerun meaningful probes, not to auto-rewrite the catalog. |

## What practitioners add

- [Geoffrey Litt, September 25, on X](https://x.com/geoffreylitt/status/2103635033961681388): the skills that survive model changes are “more spec than step-by-step instructions,” such as a good document format or interview flow. This is practitioner judgment, not a measured effect. An interview's wait for the user belongs in the contract; incidental tool order does not.
- [@kafkaup, October 16, on X](https://x.com/kafkaup/status/2110964963284033978): test hard negatives that could plausibly trigger the wrong skill, and weight false positives differently for consequential actions. [Sam's reply](https://x.com/0xSamSing/status/2110981534840950923) adds composite requests and cases where the right behavior is to stay out or clarify. Those are useful eval designs, not evidence that this catalog needs a separate classifier.

## How I would apply it to `ravn-core`

The findings reinforce [the current authoring guide's](../../plugins/agent/ravn-core/skills/writing-for-agents/SKILL.md) separation of pointers, steps, and references. Add three checks to the consolidation plan before changing shipped skills:

1. **Separate routing from execution.** Use minimal pairs that change the requested decision: “Where does dispatch live today?” → `how`; “Should dispatch get one interface?” → `codebase-design`. Add a compound request that asks for the current behavior before a design recommendation. For the proposed shared-write fold, a call to `codebase-design` is not enough: the artifact must separate independent writes or establish the actual shared invariant. Keep the standalone entry if the fold loses this behavior.
2. **Name the artifact, gate, and invalidator.** For `ship`, the artifact is the PR at a named head; every new push invalidates prior readiness evidence. For caller migration, no matches in the local inventory do not establish zero external use. For `figure-it-out`, the pre-change baseline must exist before code changes. Keep these constraints in the path where they are needed and let the agent choose interchangeable tactics elsewhere.
3. **Compare with the old catalog and with no skill.** Keep natural-language routing separate from a forced-load diagnostic: if forced use improves the outcome but native invocation misses, fix the description or the branch pointer; if both load and the outcome stays flat, change the procedure or test removing it. On each supported harness, record selected skill, actually read reference or executed check, final artifact, disallowed side effects, and cost. Use held-out positives and near misses. A shorter description is a win only if it preserves the behavior it was paying for.

Example of the shape, not a shipped rewrite:

> **Description:** Replace or remove an API that still has callers, or move callers to its replacement.
>
> **Branch:** After inventory, use the internal-caller procedure only when all callers ship together and the project permits a coordinated break. Otherwise preserve the old entry and measure external use.
>
> **Done:** Every known caller is moved or named. Delete the old API only when both local and measured external usage are zero. Unmeasured external usage keeps the old entry live.

These sources support testing narrower pointers and explicit gates. They do not establish an optimal skill count, byte budget, or universal amount of procedural detail.
